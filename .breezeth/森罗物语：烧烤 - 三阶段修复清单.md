### 🔴 P1-04 动态贴图 — 声称"本轮保留"，但设计文档定性为必做

**二阶段记录：** "P1-04：按本轮要求保留。动态取色、27 种食物段模型映射及正式贴图仍属于后续资源/渲染工作。"

**代码现状：**

**修复要求：**
- 实现 §12.4 的完整动态贴图管线：读取原食物 ItemStack 贴图 → 中段采样 4～8 色块 → 映射到 food1～food3 材质槽
- 支持生/熟/刷油/焦黑各层叠加
- 按 `物品注册名 + NBT hash + 烤制状态 + 槽位索引` 缓存，资源包重载清空
- 实现或确认 §12.3 的 27 种成品签 + 中间态模型资源
- 不能读取时使用默认色组，不允许空白

**验收：** 原版苹果、森罗牛肉、第三方模组食物各做一串秘制串，手持和物品栏显示对应食材色块而非统一占位图。

**2026-07-14 修复状态：代码与模型资源已完成。** 已生成 39 个有效模型状态，每个食材位映射 6 个动态 tint 色块；已实现原食物物品贴图中段采色、组件/NBT 缓存、资源重载清空，以及烧烤架上的刷油、逐步熟成和焦黑调色。Forge 1.20.1、NeoForge 1.21.1 编译通过，仍需按上述三类食材完成游戏内视觉验收。

### ✅ P1-14 龙蛋粉 — 复用原版龙蛋瞬移

**二阶段记录：** "P1-14：已修复。……菜刀右键龙蛋获得龙蛋粉，抢夺提高额外产量且不消耗龙蛋。"

**设计文档 §5.2：** "菜刀右键龙蛋获得粉，龙蛋瞬移但不损耗"

**最终实现：** `DragonEggPowderHandler` 只在服务端给予龙蛋粉、应用抢夺增量并消耗菜刀耐久，不取消方块交互；随后由原版 `DragonEggBlock` 完成唯一一次瞬移。

**禁止回归：** 不得在事件处理器内再次复制龙蛋方块状态、清除原位置或自行播放瞬移。事件之后原版交互仍会运行，手动瞬移与原版瞬移叠加会生成两个龙蛋。

**验收：** 菜刀右键龙蛋后只获得一批龙蛋粉，龙蛋按原版范围瞬移且世界中始终只有一个；抢夺附魔仍影响粉数量。

### 🟡 P1-09 烧烤架双形态判定逻辑偏离设计语义

**二阶段记录：** "P1-09：已修复。……双放置形态……"

**设计文档 §2.2：** "双模放置 | 地面：4 条折叠腿立式 / 方块上：平底搁置"

**代码现状：**
```java
// GrillBlock.getStateForPlacement()
return defaultBlockState().setValue(LEGGED, c.getPlayer() != null && c.getPlayer().isShiftKeyDown());
```
- 潜行时 `LEGGED=true`（有腿），非潜行时 `LEGGED=false`（平底）
- **判定依据是玩家是否潜行，不是放置目标下方是否有方块**

**设计语义应该是：**
- 放置方块时检测下方是否为完整方块顶面
- 下方有方块 → 平底搁置；下方无方块 → 折叠腿立式
- 或至少提供一个自动化判定，而非完全依赖玩家按键

**修复要求：**
- 将判定逻辑改为：放置时检测目标位置下方是否为完整方块顶面
- 若下方是完整方块 → `LEGGED=false`（平底）
- 若下方不是完整方块 → `LEGGED=true`（有腿）
- 保留手动切换方式作为备选（如斧右键切换）

**验收：** 在完整方块上放置 → 平底；在悬空位置放置 → 有腿。

### 🟡 P2-11 数据驱动 — 营养值和效果数据声明但未被使用

**二阶段记录：** "P2-11：已修复核心扩展点。固定串槽位、熟串 Buff 和调料效果类型由 `data/kaleidoscope_grilling/grilling/skewers.json` 重载"

**代码现状：**
- `GrillingDataManager.Skewer` record 声明了 `nutrition`, `saturation`, `effect`, `effectSeconds` 字段
- `skewers.json` 分别为 raw_* 和 grilled_* 定义了这些字段
- **实际营养值仅在 `ModItems` 构造 `FoodProperties` 时硬编码**，`GrillingDataManager` 的数据不驱动营养计算
- `SkewerItem.finishUsingItem()` 只使用 JSON 中的 `effect`/`effectSeconds` 决定 Buff，**不接受 nutrition/saturation**
- 数据包的 nutrition/saturation 字段被解析但从不消费

**影响：** 数据包不能覆盖营养值，只能覆盖 Buff。数据驱动的承诺只有一半兑现。

**修复要求（经设计方确认后）：**
- 方案 A：修正 `GrillingDataManager` 的文档注释或字段定义，移除 `nutrition`/`saturation`，明确营养值只由 Java 注册决定
- 方案 B：在 `SkewerItem` 中优先使用 JSON 提供的营养值回退到 Java 硬编码，完整实现数据驱动

### D-03 秘制辣椒油配方中的原料分歧 — 已通过 S-02 解决

设计 §4 表格："秘制辣椒油 | 菜籽油 + 红辣椒沫×3 + N"  
代码实现为："菜籽油 + 红辣椒粉×3"

需要设计确认：
- 使用"红辣椒沫"（已有切菜板配方）→ 代码需修改配方
- 使用"红辣椒粉"（需补充加工配方）→ 设计需更新原料名称并补充红辣椒粉加工路径

"红辣椒粉"当前注册为 `red_chili_powder`，有石磨配方 `millstone/red_chili_powder.json`（但实际加工链是红辣椒沫+石磨→红辣椒粉？还是红辣椒直接石磨→红辣椒粉？当前 JSON 为 `{"input":"kaleidoscope_grilling:minced_red_chili","output":"kaleidoscope_grilling:red_chili_powder"}`，即红辣椒沫研磨→红辣椒粉）。

所以完整链是：红辣椒 → 切菜板(×4) → 红辣椒沫 → 石磨 → 红辣椒粉。

但设计 §7 加工表没有列出"红辣椒粉"及其加工方式。需将红辣椒粉补充到设计表格中。
