# 烤串动态模型状态映射

客户端物品属性：`kaleidoscope_grilling:skewer_state`

三个食物位分别使用 `0-3`：

- `0`：空位
- `1`：食物模型 1
- `2`：食物模型 2
- `3`：食物模型 3

状态编码：

```text
stateCode = food1 * 16 + food2 * 4 + food3
propertyValue = stateCode / 64
```

约束：

- `food1` 在有效烤串中不为空。
- 穿串过程允许 `food2`、`food3` 为空。
- 三个位均非空时共有 `3 × 3 × 3 = 27` 种组合。
- 包含中间空位状态时，代码可覆盖 `3 × 4 × 4 = 48` 种组合。
- 每次插入食材时随机确定该食材使用模型 `1/2/3`，结果写入物品数据 `SkewerModelVariants`。
- 成品继续保留 `SkewerIngredients` 和 `SkewerModelVariants`，烧烤加工时必须原样复制。

## 当前实现（2026-07-18）

- 实际生成 39 个有效流程模型：一食材 3 个、二食材 9 个、三食材 27 个。
- 模型位于 `assets/kaleidoscope_grilling/models/item/skewer_states/state_<code>.json`。
- `unfinished_skewer.json` 与 `secret_skewer.json` 共用上述 39 个 predicate 覆盖。
- 每个串位的 3 种几何均直接来自美术目录中最后修改的 `mode*.json`，当前为 `mode重置第二次.json`；代码不再生成替代外轮廓。
- 39 个状态文件只负责重新组合美术提供的 9 个食物模型；模型尺寸、旋转、原始 UV 和 `display` 原样继承。
- 每个食物模型按各面 UV 的图块宽高决定 X×Y×Z 分区数，并取最近整数；不再根据几何尺寸的小数猜测数量。内部面不渲染，各外表面 UV 按原比例裁切，外轮廓与旋转保持不变。
- 客户端从对应原始 `ItemStack` 的物品模型粒子贴图中央区域采样，并按空间位置缩小为 4×4 色彩图；低 Z 对应原贴图底部，而不是随机铺设统计色。
- 颜色使用 Lab 感知色差合并至最多 8 类；透明格继承最近有效颜色，孤立的极端噪点会并入相邻主色。
- tint 索引编码为 `slot * 128 + face * 16 + cell`。上下表面使用 X×Z 位置，前后侧面使用 X×Y 位置，左右侧面使用 Z×Y 位置；`face` 依次为上、下、低 Z、高 Z、左、右。
- 上表面轻微提亮，底面与四个侧面按不同幅度压暗；深色食材会自动降低明暗处理强度，避免直接变黑。
- 烤制阶段按空间边缘局部暖化和焦化，边缘比中央更早出现焦褐色，不再对整个食物使用完全相同的棕色覆盖。
- 采色缓存按物品注册名与组件/NBT hash 区分，资源包重载时清空。
- 烧烤架渲染复制物品并写入仅客户端使用的视觉阶段，不修改服务器保存的真实串签数据。
- 视觉阶段为：原色、刷油增亮、浅熟、中熟、熟制暖色、焦黑。
