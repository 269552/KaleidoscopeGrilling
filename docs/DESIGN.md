## 一、模组概述

为森罗厨房扩展烧烤玩法，新增烧烤架方块、榨油器、手持穿串系统、刷油翻面撒料交互、16 种固定烤串、2 种凉菜、2 种熔炉熟制食物，以及配套作物与食材加工与榨油体系。

## 二、核心系统

### 2.1 手持穿串系统

- **左手（副手）：** 木棍
- **右手（主手）：** 食材
- **操作：** 右键消耗食材，播放第一人称“往左手捣鼓”动画（约 0.4 秒）
- **流程：** 重复操作直到配方完成，木棍变为成品生串
- **辅助：** 签谱可记录固定生串配方；左手木棍、右手签谱右键可一次性消耗背包食材完成穿串
- **交互：** 全程手持交互，无 UI 界面

#### 签谱

- **来源：** 使用森罗厨房的 **空白菜谱** 与任意本模组 **生串** 合成，得到对应生串的 **签谱**。
- **记录内容：** 签谱记录该生串的食材顺序、食材数量与输出生串，不新增独立配方单体系。
- **使用方式：** 玩家左手持木棍、右手持签谱右键，系统从背包中检查并扣除签谱记录的食材，直接生成对应生串。
- **缺料提示：** 若背包食材不足，不消耗任何材料，并提示缺少的食材与数量，提示风格参考森罗厨房菜谱的 `缺少：材料×数量`。
- **展示方式：** 签谱和森罗厨房菜谱一样支持挂在墙上；方块状态显示其记录的对应串类图案，用于直观看出这是哪一种烤串签谱。
- **定位：** 签谱只辅助固定配方生串的快速穿串；秘制烤串仍通过手持木棍与食材逐个穿串生成。

#### 烤串放置与烤串盘

- 固定串、秘制串、生串和熟串均可放置；未完成的半成品串不能食用，也不作为成品串放置。
- 主手持串 `Shift + 右键`任意完整方块上表面，生成一个引用森罗厨房盘子模型的烤串盘并放入第一串。
- 每盘最多放置 5 串，按模型的 `wood1` 至 `wood5` 依次填充；食物外观直接使用对应烤串物品自身的模型。
- 手持烤串右键已有烤串盘可继续追加；空手右键按相反顺序取回。取走最后一串后保留空盘，左键破坏空盘时直接消失。
- 左键破坏有串的盘子时，掉落一个“有烤串的盘子”，完整保存各串的 `ItemStack`、NBT、食材、制作人、熟度、调料和热状态。
- “有烤串的盘子”普通右键自动食用当前饱食度最高的烤串；饱食度相同时优先序号靠前者。食用后删除该串并压紧剩余序号，最后一串吃完后盘子物品直接消失。
- “有烤串的盘子”主手 `Shift + 右键`完整方块上表面可重新放置，并恢复整理后的烤串顺序。
- 已放置或装入盘子的烤串继续按世界游戏时间自然变凉，不暂停热状态倒计时。
- 强交互优先级：主手 `Shift + 右键`负责放置；副手 `Shift + 右键`负责拆串；不按 Shift 时优先执行目标方块交互（烧烤架/烤串盘），否则食用当前手中的烤串。
- 此处的烤串盘是展示、携带和食用容器，不代表恢复第 3.2 节暂缓的“盘装烧烤料理”流程。

### 2.2 烧烤架

| 属性 | 设定 |
| :--- | :--- |
| 模型 | 长方形炭火槽 + 平行金属烤网 |
| 双模放置 | 地面：4 条折叠腿立式 / 方块上：平底搁置 |

### 2.3 烧烤流程

#### 串类流程

放串 → 刷油 → 翻面×4 → 撒料 → 取出

| 步骤 | 操作 | 说明 |
| :--- | :--- | :--- |
| 放串 | 手持生串右键 | 单排平铺烤网，最多 3 串 |
| 刷油 | 油壶右键 | 放入烤串后才能刷油；开烤硬条件，覆盖所有可刷油食物并按数量消耗油壶容量，产生嘶嘶粒子 |
| 翻面 | 徒手右键×4 | 参照森罗炒锅“四次翻炒即完成”的判定；每次所有串播放 1 秒翻转动画，动画期间不能再次翻转 |
| 撒料 | 调料瓶右键 | 出炉前硬条件；不撒料不能取出 |
| 取出 | 右键逐个取 / 潜行右键全取 | 仅在完成或烤焦阶段，且已撒料后可取出 |

**流程判定参照《森罗物语：厨房》炒锅翻炒食物：**

- **完成条件：** 刷油后不再等待额外的 1200 tick 烤制进度；完成 4 次有效翻转后立即进入完成阶段。烤焦计时从已点燃烤架放入第一串食物时开始，刷油和翻面不会重置计时。
- **刷油顺序：** 不同于森罗炒锅“先起锅烧油”，烧烤必须先放入烤串，再对食物刷油；空烤架不能刷油。
- **交互提示：** 未点燃时尝试放串提示“缺少必要的热源”并拒绝放入；未刷油时尝试翻面提示“等待刷油”；每次有效翻面后提示当前翻面次数；完成但未撒料时尝试取出提示“烹饪已完成，等待撒料”；完成且已撒料后自动提示“烹饪已完成，等待取出！”。空烤架与翻面冷却期间不显示状态提示。
- **缺少刷油：** 食物不能进入正式熟成和翻面流程，提示缺少油脂；但只要已点燃烤架上存在烤串，烤焦计时仍会继续，拖延刷油也可能直接烤焦。
- **刷油消耗：** 与撒料一致，一次刷油覆盖当前烤架上所有可刷油食物，并按 **本次覆盖的可刷油食物数量** 消耗油壶容量；1 点油可刷 1 串。
- **缺少翻面：** 未完成 4 次翻转时不会自然完成；若通过破坏或特殊交互中断，按 **迷之烤串** 处理。
- **完成取出窗口：** 第 4 次翻转动画触发后直接进入完成阶段，可取出正常成品，不再显示或等待 1200 tick 进度。
- **翻转动画：** 每串分别记录动画起点和随机高度；高度曲线沿用森罗炒锅的抛物/正弦式起落计算。模型绕局部 Y 轴（即与玩家面向对应的水平轴）旋转 180°，每次翻转累计保留朝向。
- **烤焦超时：** 从已点燃烤架放入第一串食物起累计 40 秒后进入烤焦阶段；刷油、翻面和进入完成阶段均不重置该计时。
- **烤焦取出：** 烤焦阶段取出获得失败成品，命名方式参考森罗炒锅的 **黑暗料理** 风格，但烤串与料理是两套物品体系，串类失败物不直接混用森罗料理物品。
- **烤焦后继续超时：** 烤焦阶段继续超时则清空烤架槽位，并掉落少量木炭；等价于炒锅烧糊后最终清空并掉木炭。
- **未完成取出：** 没熟时不能取出正常成品；若通过特殊交互强行中断，也按 **迷之烤串** 处理，不对玩家造成烫伤或扣血。
- **烤架破坏掉落：** 破坏烧烤架不会保留烤制进度，也不对玩家造成烫伤或扣血；空槽不掉落。未刷油、未进入烤制的生串掉回对应生串；已刷油但未完成、完成但未撒料、或其他不能正常取出的串统一掉落 **迷之烤串**；已完成且已撒料的串掉落正常成品；焦化阶段掉落对应烤焦失败物。油壶、调料瓶等手持工具不存入烤架，因此不参与破坏掉落。
- **碗装/载体类失败食物：** 若后续出现需要碗等载体盛装的烧烤失败产物，可参考森罗厨房的迷之炒菜 / 黑暗料理逻辑；但烤串与料理仍是两回事，串类失败物保持独立命名与独立物品。
- **缺少撒料：** 不能取出，提示需要撒料；必须使用调料瓶完成撒料。调料瓶是基础烧烤工具，制作门槛低；基础撒料只负责完成出炉流程，高级材料才决定额外调料 Buff。调料 Buff 是否触发仍由调料瓶内容和热状态独立计算。
- **视觉阶段：** 生肉色 → 浅褐 → 金褐 → 焦糖金黄 → 冒黑烟 → 焦黑。

#### 盘装类流程

当前版本暂不实现盘装烧烤；烧烤架只处理串类。后续若恢复盘装类，再重新定义容量占用、刷油、撒料、失败产物与载体逻辑。

### 3.1.1 固定烤串 Buff 设计（暂定）

固定烤串的 Buff 不重新发明一套效果，而是优先参考《森罗物语：厨房》中同源食材制作出的成熟料理。烤串定位为“一串小份料理”，因此继承效果类型，但按食材规模缩短持续时间。

**持续时间折算规则：**

```text
烤串 Buff 时间 = 参考料理 Buff 时间 × 烤串有效食材数 ÷ 参考料理有效食材数
```

- **参考料理有效食材数**：只计算与该 Buff 来源相关的主食材等价量，不计算碗、盘、锅底、油、糖等辅助载体。
- **烤串有效食材数**：按原料等价量折算，而不是按串上的格数折算。例如：2 个牛肉块 = 1 个牛肉；3 片土豆片 = 1 个土豆；3 片馒头片 = 1 个馒头。
- 辣椒、折耳根沫等调味类食材通常不单独增加主 Buff 时间，除非该 Buff 本身来自调味食材。
- 结果按 5 秒取整；不足 5 秒的趣味/负面效果按 5 秒处理。
- 不设置统一的正面 Buff 最短时间；如果某些单串效果过短，后续作为平衡项单独提高。
- 热属性会在食用时将食物自身 Buff 时间翻倍；调料 Buff 独立计算，不参与本表折算。

| 成品烤串 | 参考厨房料理 | 继承 Buff | 折算依据 | 暂定时间 |
| :--- | :--- | :--- | :--- | :--- |
| 烤牛肉串 | 红烧牛肉 | 活力（Vigor） | 2 个牛肉块 = 1 个牛肉；参考红烧牛肉 6 个牛肉等价 90 秒 | 15 秒 |

### 3.1.2 固定烤串饱食度与饱和倍率（暂定）

固定烤串的饱食度先按烤熟成品确定，再按比例折减为未烤制生串。熟串定位为“小份烧烤料理”，不直接等同整份锅料理；生串定位为“临时可吃但不鼓励跳过烧烤流程”。

**折算规则：**

- 熟串饱食度参考同源料理与主食材等价量，再按烧烤小份定位微调。
- 熟串饱和倍率参考同源料理；多数普通烧烤控制在 `0.3-0.8`，高饱和主食/凉菜可超过 `0.8`，怪味串允许更低。
- 生串饱食度 = `max(1, floor(熟串饱食度 × 0.5))`。
- 生串饱和倍率 = `熟串饱和倍率 × 0.5`；怪味串熟串饱和倍率为 `0` 时，生串也为 `0`。
- 所有生串都可以食用。
- 生肉类生串不附加饥饿、反胃、中毒等负面效果。
- 生串不提供正面 Buff；生猪儿虫串、生粘液串、生末影珍珠串保留 3 秒反胃（Nausea）作为趣味负面效果，不继承其他 Buff。
- 热属性只影响 Buff 持续时间，不提高饱食度或饱和倍率。

### 3.1.3 烤串食用体验

本模组的烤串食物主打“拿起来就吃”的烧烤手感，进食节奏应明显短于普通食物。

- **适用范围：** 本模组固定烤串、秘制烤串，以及对应可食用生串。
- **进食时间：** 暂定 **16 tick**（约 0.8 秒），参考原版快速食物手感；后续若实际体验过快或过慢，再统一微调。
- **完成音效：** 玩家吃完本模组烤串食物时，额外播放原版打嗝音效 `ENTITY_PLAYER_BURP`，表现为“嗝~”的收尾反馈。
- **触发时机：** 只在食用完成并实际结算营养与效果后播放；中断进食不播放。
- **非烤串食物：** 烤红薯、烤鸡翅、凉菜和森罗厨房联动料理不默认套用该快速进食规则，除非后续单独指定。

### 3.1.4 烧烤失败食物

### 4.1 热属性系统

烧烤食物附加 **热/凉** 属性，默认状态为凉（不显示标签）。

| 底油 | 热属性持续时间 | 说明 |
| :--- | :--- | :--- |
| 普通菜籽油 | 60 秒 | 基础底油，持续时间短 |
| 辣椒油（川味） | 10 分钟 | 川味底油，显著延长热属性 |
| 熔岩辣椒油 | 20 分钟 | 顶级底油，超长保温 |
| 原版油脂（猪油/牛油等） | 60 秒 | 可与菜籽油互换使用 |

- 使用森罗厨房 **油壶** 中的对应底油刷在食物上，赋予食物热属性及对应持续时间
- 油壶复用森罗厨房已有方块与贴图，但需要修改森罗厨房油壶容量逻辑，最大容量改为 **64 点 = 8 桶油**
- 油壶容量按点计数；一次刷油覆盖当前烤架上所有可刷油食物，并按覆盖数量消耗容量，**1 点油 = 1 串 / 1 个可刷油食物**
- 油量换算：**1 桶油 = 8 点油**，因此 1 个满油壶可容纳 8 桶油，可刷 64 串
- 油壶需要扩展记录油种；空油壶可装入任意支持油种，已有油的油壶只能继续加入同类油
- 油壶 HUD 不再只显示 `数量：xxx`，而是按油种显示：`油脂：xxx个`、`菜籽油：xxx点`、`辣椒油：xxx点`、`熔岩辣椒油：xxx点` 等
- 资源表现上必须修改油壶的溢出油色：菜籽油、辣椒油、熔岩辣椒油等不同油种在油壶口、滴落/溢出像素、刷到食物上的油光层上使用不同颜色。
- 刷油动作表现需要出现“刷子”视觉：玩家仍使用油壶物品交互，但动画/第一人称表现/使用态贴图中应看到刷子或刷头蘸油刷过烤串。
- 刷油动作刷子不是固定不变资源，而是随油种变化的动作表现：菜籽油刷子、辣椒油刷子、熔岩辣椒油刷子分别使用对应油色的刷头、滴油和油印表现。
- 刷油动作刷子按不可获取物品处理，不放入创造物品栏，Tooltip 注明“不可获取物品 / 仅用于刷油动作表现”；它只服务同一油壶系统的动作表现，不新增可获取的独立油刷工具，也不恢复搪瓷油刷杯。
- 空油壶右键装有菜籽油的 **大缸** 可直接装入菜籽油；大缸装水时不能给油壶补油
- 三种油桶都需要对应 **桶装物品贴图**：菜籽油桶、辣椒油桶、熔岩辣椒油桶。
- 三种油都需要对应 **流体颜色 / 倒出颜色 / 油壶溢出颜色**，并保持桶装物品、倒入表现、油壶壶口、滴落/油印与刷到食物上的油光层颜色一致。
- 菜籽油桶、辣椒油桶、熔岩辣椒油桶等桶装油右键方块状态的油壶可向油壶加油；目标油壶必须为空油壶或同类油壶，并播放对应油色的倒入表现。
- 菜籽油、辣椒油和熔岩辣椒油作为标准流体时均可倒入 **大缸**；大缸内已有流体时必须保持同类。方块状态油壶仍按自身油种与容量规则交互。
- “倒出/倒入表现”只用于桶装油向容器灌入；刷油仍使用油壶 + 对应油种刷子视觉，不使用倒油动作。
- 刷油后食物进入正式烤制阶段，并叠加油光层作为视觉反馈
- 热属性持续期间食物显示 **🔥热** 标签
- **食用效果加成：** 食用处于热属性期间的食物，该食物本应提供的所有 Buff 时长 **翻倍**
- 凉食默认为无标签不显示
- 不同底油仅影响热属性时长，不叠加
- **适用范围：** 本模组食物、原版食物及其他附属模组食物均可附加热属性
- **开放接口：** 其他模组可通过 `HotFoodApi.makeHot(stack, level, seconds)` 为任意食物指定本次热属性时间，或通过 `HotFoodApi.registerHeatDuration(item, seconds)` 注册该物品的默认时间；未注册时接口默认使用 30 秒。
- **跨模组 Buff：** 食用热食前后统一快照玩家状态效果，对本次食用新增或延长的 Buff 时长进行一次翻倍，因此兼容其他模组在食用完成代码中动态添加的效果，并避免烤串自身逻辑重复翻倍。
- **可选熔炼热食：** COMMON 配置 `hot_food.enableSmeltedFood` 默认为 `false`；开启后，玩家从熔炉、烟熏炉等熔炼结果槽取出可食用成品时自动附加热属性。系统以成品的可食用属性判断，矿物、玻璃等非食物不会获得热属性；其他模组食物同样支持。
- **熔炼默认时间：** `hot_food.smeltedFoodSeconds` 默认为 `30` 秒，可在配置文件中修改。当前触发点为玩家取出熔炼成品，漏斗等自动抽取不触发。
- **互通：** 桶装菜籽油可作为菜籽油流体来源，用于大缸、油壶与起锅烧菜；原版油脂也可为食物赋予 60s 热属性，但不能作为烧烤刷油材料

### 4.2 榨油系统

完整榨油流程：

```text
油菜籽（成熟油菜随机掉落 2-4 个）→ 石磨研磨 → 菜籽粉 → 8 个菜籽粉围绕 1 个小麦合成油饼 → 榨油器压制 → 菜籽油
```

**新增流体与桶装物品：**
- 新增 **菜籽油** 流体与 **菜籽油桶**。
- 新增 **辣椒油** 流体与 **辣椒油桶**。
- 新增 **熔岩辣椒油** 流体与 **熔岩辣椒油桶**。
- 后续若增加其他底油，统一按“对应流体 + 对应桶装物品 + 油壶油种记录”的结构扩展。
- 桶装油是大缸、油壶、合成配方与自动化管线之间的标准中间形态；油壶仍按点消耗，大缸内部按标准流体单位（mB）存储并在 HUD 中显示。
- 大缸接受原版及其他模组的任意标准流体（包括水、岩浆和各类模组流体）；空缸可接收任意流体，非空时只能继续加入完全相同的流体及组件。
- 三种油流体都需要独立颜色配置，用于流体本体、桶装物品、倒出/灌入动画、油壶溢出像素和烧烤油光层。

**新增长方块：榨油器**
- 模型：木制框架 + 中部压板 + 底部出油槽
- 合成：原木×4 + 木栅栏×2 + 铁块×1 + 漏斗×1；九宫格正中留空，底部中间为漏斗出油口
- 榨油器专门用于制作菜籽油，辣椒油与熔岩辣椒油在菜籽油基础上继续加工。

**新增容器：大缸**
- 合成：砖块/陶瓦×7 + 桶×1
- 容量：**64,000 mB（64 桶）**，与原 64 桶设计容量一致
- 使用标准流体容器交互：支持桶、其他模组流体容器以及管道/能力接口的输入输出，不再为每一种流体编写专用交互
- 大缸记录完整流体堆栈；空缸可接收任意流体，已有内容的大缸只能继续加入同类且组件一致的流体
- 破坏大缸时，当前流体种类、数量及组件保存在掉落物中，重新放置后恢复
- 榨油器仍只向可接收菜籽油且剩余容量足够的大缸输出，不会覆盖或混入其他流体

**榨油器使用步骤：**
1. **放置大缸：** 将 **大缸** 放置在榨油器附近作为集油容器；大缸不放入榨油器内部，它们之间不需要硬性连接。
2. **装饼：** 手持 **油饼** 右键榨油器放入，按由下到上的顺序显示；一批固定装入 **4 个**，未装满不能开始压榨。
3. **压榨：** 榨油器有 **16 个压榨进度**；玩家手持任意耐久状态的铁砧右键榨油器，每次增加 **4 点进度**；手持 `kaleidoscope_grilling:press_stones` 物品标签中的物品右键，每次增加 **1 点进度**。两种工具共用 **0.5 秒（10 tick）**操作冷却；动画总长 9 tick，并在第 6 tick 的命中帧结算进度。
4. **出油：** 进度满 16 后，榨油器查找附近可接收菜籽油的大缸；若找到空大缸或已有菜籽油且未满的大缸，则将本轮 **4 桶菜籽油**直接移动进去，并从正面弹出 **4 个油渣**。默认 **1 个油饼 = 1 桶菜籽油 = 8 点油**。

**压榨模型阶段：**

- 默认不渲染 `oil1-oil5`，`hitblock` 位于原位。
- 放入油饼时，依次显示 `oil1` 中由下到上的 1-4 层。
- 进度 1-4：`hitblock` 下移 2 像素，`oil1` 切换为 `oil2`。
- 进度 5-8：`hitblock` 累计下移 4 像素，`oil2` 切换为 `oil3`。
- 进度 9-12：`hitblock` 累计下移 5 像素，`oil3` 切换为 `oil4`。
- 进度 13-15：`hitblock` 累计下移 6 像素，`oil4` 切换为 `oil5`。
- 命中帧达到 16 后，先维持 `oil5` 与压块最低位置 10 tick；随后成功出油时 `hitblock` 归位，全部油饼层隐藏，并弹出 4 个油渣。若附近没有可接收整批菜籽油的容器，则进度退回并锁定为 **15/16**，保持 `oil5` 与压块最低位置，不回弹；玩家之后手持任意物品或空手右键榨油器均可重新检查，后放入有效容器后再次检查即可完成出油并回弹。
5. **缺少大缸：** 若附近没有可接收菜籽油的大缸，或附近大缸已装水/已满/类型不符，则本次不会完成榨油，并提示需要可接收菜籽油的大缸。

**压榨进度来源：**
- 不再使用铁砧、沙子、红沙或砂砾等下落方块触发压榨。
- 有效工具右键只预约敲击并广播 9 tick 动画，不在起手帧修改进度或播放砸击声。动画从头顶准备姿态直接开始，仅表现向正前方砸下；0-6 tick 使用三次加速曲线，后段明显加速，第 6 tick 为命中帧，最后 3 tick 平滑回到普通姿态。
- 命中帧由服务端统一增加进度、播放铁砧砸落声、发送冲击粒子并提示当前进度，避免网络延迟或客户端掉帧造成声音早于动作。
- 第一人称取消原版手持绑定，分别渲染双臂与中央工具；第三人称跳过物品的 `translateToHand`，按玩家身体坐标和同一动画曲线独立渲染工具，因此铁砧或石块不再僵硬地粘在右手模型上。
- 石头标签压榨使用同一套第一/第三人称砸落动画和反馈，每次只提供 1 点进度；其他模组可通过向 `press_stones` 物品标签追加物品扩展可用工具。
- 榨油器具有水平朝向；成功出油后，同批油渣会从榨油器正面自动弹出，不再要求玩家空手取出新产生的油渣。
- 对外提供 `OilPressApi.addProgress(level, pressPos, amount)`，其他模组可按同一 0～16 进度单位接入自定义压榨设备或交互。
- 预留进度 API：其他模组可通过 `OilPressApi.addProgress(level, pressPos, amount)` 提交压榨进度，用于接入机械化压榨设备或自定义交互。
- 预留容器 API：其他模组可通过 `OilPressContainerApi.register(id, handler)` 注册可接收菜籽油的流体容器。处理器实现 `probe(level, pos, canolaBuckets)` 与 `insert(level, pos, canolaBuckets)`；探测结果使用 `NOT_CONTAINER / READY / FULL / INCOMPATIBLE`，榨油器只会向返回 `READY` 且成功执行插入的容器输出整批 4 桶菜籽油。内置大缸也通过同一 API 注册。

**分装说明：**
- 满大缸可分装为 **64 桶菜籽油**，也可直接给空油壶或同类菜籽油油壶补油
- 桶装菜籽油可右键方块状态的 **油壶** 加油；油壶必须为空或已装菜籽油
- 菜籽油同时也是 **辣椒油** 与 **熔岩辣椒油** 的基底

### 4.3 调味系统

调味系统参考森罗酒馆调制鸡尾酒的“放置容器、逐步加料、取回后摇晃”流程，但不使用森罗酒馆的 QTE。调料瓶不再使用玻璃瓶作为直接容器，而是使用本模组的 **空调料瓶**。

调料瓶有两层职责：

- **流程功能：** 调料瓶是基础烧烤工具，制作简单。烤串完成后必须撒料才能取出；普通基础撒料只负责让烧烤完成出炉，不提供额外 Buff。
- **强化功能：** 调料瓶中无论加入何种调料，最终成品都统一叫 **特制调料**；其中加入红石粉、火药粉、折耳根粉、不死图腾粉、龙蛋粉等高级材料后，才根据材料组成提供额外调料 Buff、等级和时长强化。
- **消耗方式：** 特制调料拥有 16 次使用次数，以耐久条和 Tooltip 同时显示。一次撒料会覆盖当前烤架上所有可以撒料的半成品串，并按 **本次覆盖的可撒料半成品串数量** 消耗等量耐久；例如 3 串同时撒料则消耗 3 点耐久。耐久为 0 时不破坏瓶子，而是变回 **空调料瓶**。

**制作流程：**
1. 将 **空调料瓶** 放置为方块状态，作为可见的调制容器；不需要额外调味台。空调料瓶可放在任意完整方块顶面。
2. 手持各种调料材料右键空调料瓶，依次加入材料；每次添加播放对应动画与音效，并把材料列表写入调料瓶 NBT。
3. 已加入材料的空调料瓶在方块状态和物品状态都显示 Tooltip，列出已加入材料、容量占用和可预期效果。
4. 加料完成后打掉调料瓶，掉落物品名改为 **待摇晃的调料**。
5. 手持 **待摇晃的调料** 开始摇晃，持续 4 秒；不使用 QTE。
6. 手持 **待摇晃的调料** 潜行右键方块，可将其重新放置为调料瓶并保留已加入材料，以便继续加料；普通右键仍执行摇晃。
6. 摇晃完成时播放结束声音与粒子效果，物品变为 **特制调料**，获得 16 次使用次数，可用于撒料。

**取回与还原：**
- 未加料的空调料瓶方块被打掉时，掉落 **空调料瓶**。
- 已加料且满足基础辅材要求的调料瓶方块被打掉时，掉落 **待摇晃的调料**。
- 若缺少基础辅材中的任意一种，打掉时不进入待摇晃状态，并提示缺少基础辅材。
- **待摇晃的调料** 和已经调制完成的 **特制调料** 都可以通过合成方式还原为 **空调料瓶**，用于主动清空材料与重做配方。
- 特制调料耐久为 0 时自动清空材料 NBT，变回真正的 **空调料瓶**。

**摇晃规则：**
- 摇晃需要连续维持 4 秒。
- 松开右键、切换物品或被打断时，摇晃进度重置。
- 材料加入顺序不影响最终效果，只记录各材料数量；顺序仅用于 Tooltip 和 HUD 展示。

**HUD 反馈：**
- 当玩家目光聚焦在调料瓶方块上时（无论是否已加料），显示调制 HUD。
- HUD 使用半透明深色面板 + 左侧金色装饰条，显示：配方标题、容量进度条、已加入材料列表和效果预览。
- **基础辅材（绿辣椒粉、花椒、洋葱粉）始终固定在 HUD 顶部显示**，缺少时以红色”缺少”标注，已有时显示数量。底部不再显示基础辅材总状态。
- 瓶身预览以物品图标形式显示在标题右侧。
- HUD 不区分基础/高级材料分区；已加入的升级材料直接显示在基础辅材下方。
- 放置调料瓶 HUD 与油壶 HUD 默认不新增独立贴图资源，优先使用原版/森罗既有渲染能力绘制高级面板、文字、图标与进度信息。
- 空调料瓶若已经带有材料 NBT，即使尚未摇晃，也必须在 Tooltip 中显示已加入材料和当前状态，避免玩家丢失调制信息。

**容量规则：**
- 一瓶最多添加 **8 份材料**
- **基础辅材（3 份，固定）：** 绿辣椒粉 + 花椒 + 洋葱粉（各至少 1）
- **剩余 5 个空位** 可自由分配升级材料
- 玩家需要自行权衡：**4 份同种升 II 级**，还是 **各 1 份凑多种 Buff**
- 容量已满时继续加料不会消耗材料，提示 **调料瓶已满**；HUD 同步显示剩余可加入数量为 0。

| :--- | :--- |
| 绿辣椒粉 | 基础辣味 |
| 花椒 | 麻味来源 |
| 洋葱粉 | 基础底味 |

| :--- | :--- | :--- |

| 火药粉 | 原版火药 | 力量 |

**Buff 规则：**
- 调料 Buff 与食物本身的 Buff **互不干扰，独立计算时长**
- **必须为热食**（带有 🔥热 属性）才触发调料 Buff
- 普通基础撒料不提供额外 Buff，只满足烧烤出炉流程
- 基础持续时间为 **3 分钟**
- 同种材料添加 **4 份** 升级为 II 级效果（不死图腾粉和折耳根粉除外）
- **适用范围：** 特制调料不仅用于烧烤撒料，也可在 **森罗炒锅** 炒菜时添加，同样触发对应 Buff
- Buff 材料沿用当前表，不再额外发明新材料效果。

### 12.3 动态模型

使用统一串签模型，不为每种食材单独制作模型。

模型基础：

- 空签模型 1 个
- 预留 3 个食材槽：`food1`、`food2`、`food3`
- 每个槽位负责显示一个串入食材的动态色块材质

模型组合：

空签是独立模型状态。一旦玩家左手木棍、右手食材并右键完成第一次穿串，串签就进入半成品状态，此时 `food1` 必定有食物，不会为空；后续槽位根据穿串进度可以为空。

需要区分“满签成品状态”和“穿串过程状态”：

| 槽位 | 3 种状态 |
| :--- | :--- |
| `food1` | 食材姿态 A / 食材姿态 B / 食材姿态 C |
| `food2` | 食材姿态 A / 食材姿态 B / 食材姿态 C |
| `food3` | 食材姿态 A / 食材姿态 B / 食材姿态 C |

满签或成品签拥有 3 个食物槽，每个槽位 3 种食材模型状态，因此成品签状态数为：

```text
food1 × food2 × food3 = 3 × 3 × 3 = 27
```

穿串过程中，后续槽位允许为空：

| 进度 | 槽位状态 |
| :--- | :--- |
| 空签 | 独立空签模型 |
| 已串入 1 个食物 | `food1` 为 3 种食材模型之一；`food2` 与 `food3` 为空 |
| 已串入 2 个食物 | `food1`、`food2` 各为 3 种食材模型之一；`food3` 为空 |
| 已串入 3 个食物 | `food1`、`food2`、`food3` 各为 3 种食材模型之一，即 27 种成品签状态 |

换句话说，`food1` 一旦进入半成品串就不为空；`food2`、`food3` 在穿串过程中各自可能是 `空 / 食材模型 A / 食材模型 B / 食材模型 C`。有效流程不会出现 `food2` 为空但 `food3` 已有食物的跳格状态。

这 27 种状态在生串、熟串、烤焦串之间共用；不同熟制阶段通过动态色块、油光层、熟制层和焦黑层表现，不额外增加模型状态。食材本身也不增加模型数量，视觉差异由动态色块映射产生，因此 27 种成品签状态可以承载无限种食材表现。

姿态规则：

- 食材串入时，为对应槽位随机选择一个食材模型姿态，并写入该串的 NBT。
- 随机结果在物品栏、手持、烤架上保持一致，不随客户端刷新变化。
- 拆串后再重新串入，重新随机姿态。
- 固定配方串转化为独立物品时，默认不保留半成品姿态；如后续希望固定串也有轻微差异，可保留姿态 NBT 作为扩展。

### 12.4 动态贴图

动态贴图是串签系统的必做核心能力，不作为可选二阶段内容。固定 14 串可以拥有独立贴图，但秘制烤串必须能直接读取原食物贴图并动态显示串入食材。

流程：

原食物贴图
↓
取贴图中段 4-8 个代表性色块
↓
映射到串签模型预留食材槽

优点：

- 自动支持原版食物
- 自动支持森罗厨房
- 自动支持第三方食物
- 新食物无需额外建模
- 不需要复杂识别透明边界或主体轮廓，稳定性优先

映射规则：

1. 每个串入食材保存原始 `ItemStack/NBT`，渲染时读取其物品栏显示贴图。
2. 从贴图中段区域采样 `4-8` 个非透明或高可见度色块，作为该食材的代表色组。
3. 按模型预留的食材槽位顺序映射：第 1 个串入食材 → `food1`，第 2 个串入食材 → `food2`，第 3 个串入食材 → `food3`。
4. 食材槽的几何形状、位置和 UV 由模型文件决定；代码只负责把代表色组写入对应材质槽。
5. 生串使用原代表色；刷油叠加油光层；熟串叠加暖色熟制层；烤焦叠加焦黑层。
6. 若贴图无法读取，则使用默认占位色组；不允许出现空白食材槽。
7. 生成结果按 `物品注册名 + NBT hash + 烤制状态 + 槽位索引` 缓存，资源包重载时清空缓存。
8. 色块采样结果不写入物品 NBT；只保存原始食材 `ItemStack/NBT` 与槽位姿态，客户端渲染时计算并缓存色块结果。

实现记录（2026-07-14）：

- 已采用玩家提供的木棍和基础食物几何，补齐 `3 × 3 × 3` 姿态。
- 已生成一食材 3 种、二食材 9 种、三食材 27 种，共 39 个有效流程模型状态。
- 每个食材位拆分为 6 个独立 tint 色块，从原食物物品模型贴图中段读取非透明颜色后映射。
- 已支持原版、森罗厨房及第三方模组物品的原始 `ItemStack` 组件/NBT 区分。
- 已实现默认占位色、最多 512 项的客户端采色缓存以及资源包重载清空。
- 已实现烧烤架中的原色、刷油增亮、逐步熟成、熟制暖色和焦黑视觉阶段；阶段数据只写入渲染副本。
- Forge 1.20.1 与 NeoForge 1.21.1 使用相同模型资源，各自注册物品颜色处理和 Sprite 像素访问。

### 12.6 秘制烤串

未匹配固定配方时生成，最多 3 种食材。秘制烤串的营养数值由本系统统一计算，不直接叠加原食材的饱食度与饱和倍率；原食材的食用效果通过模拟食用流程继承。

**熟秘制烤串属性：**

```text
熟秘制串饱食度 = max(1, floor((总饱食度 - 最低饱食度) × 系数))
熟秘制串饱和倍率 = clamp(平均饱和倍率 × 系数, 0, 0.8)
```

| 食材组合 | 系数 | 设计目的 |
| :--- | :--- | :--- |
| 无重复食材 | 0.6 | 鼓励混搭 |
| 有重复食材 | 0.5 | 避免纯高价值食材堆叠 |

**生秘制烤串属性：**

```text
生秘制串饱食度 = max(1, floor(熟秘制串饱食度 × 0.5))
生秘制串饱和倍率 = 熟秘制串饱和倍率 × 0.5
```

**示例：**

| 食材 | 原饱食度 | 原饱和倍率 |
| :--- | :--- | :--- |
| 牛肉 | 3 | 0.3 |
| 洋葱 | 1 | 0.2 |
| 辣椒 | 1 | 0 |

```text
总饱食度 = 5
最低饱食度 = 1
平均饱和倍率 = 0.166
无重复系数 = 0.6

熟秘制串饱食度 = floor((5 - 1) × 0.6) = 2
熟秘制串饱和倍率 = 0.166 × 0.6 ≈ 0.1
生秘制串饱食度 = floor(2 × 0.5) = 1
生秘制串饱和倍率 = 0.05
```

### 12.7 效果继承

秘制烤串保存每个串入食材的原始 `ItemStack` 与 NBT。玩家食用秘制烤串时，先结算秘制烤串自身公式计算出的饱食度与饱和倍率；随后按串入顺序依次模拟食用每个原始食材，只触发原食材的食用效果、药水效果、森罗自定义效果或第三方模组食物逻辑，不继承原食材的饱食度与饱和倍率。

```text
食用秘制烤串
→ 结算秘制烤串自身饱食度/饱和倍率
→ 读取第 1 个原始食材 ItemStack/NBT 并模拟食用效果
→ 读取第 2 个原始食材 ItemStack/NBT 并模拟食用效果
→ 读取第 3 个原始食材 ItemStack/NBT 并模拟食用效果
→ 屏蔽或抵消原食材本身带来的饱食度/饱和倍率变化
```

**继承边界：**

- 继承原食材的食用后效果，而不是提前登记食物白名单。
- 不继承原食材的饱食度与饱和倍率，营养值只来自秘制烤串公式。
- 原食材自身的容器返还、特殊消耗、NBT 行为尽量按模拟食用流程保留；若会导致复制或破坏性副作用，再进入实现阶段单独屏蔽。
- 生秘制烤串也按同一继承规则触发原食材效果，但自身饱食度与饱和倍率按 50% 折减。
- 热属性只翻倍秘制烤串自身或原食材模拟食用时产生的可翻倍 Buff 时长，不改变营养值。

兼容：

- 原版食物
- 森罗厨房食物
- 第三方模组食物

Tooltip 不枚举继承效果，避免第三方食物效果过多导致信息爆炸；具体效果由实际食用结果体现。

### 12.10 第三方串类兼容接口

串类兼容采用“数据包优先、Java API 补充”的方式，普通附属模组不需要直接依赖 Forge 或 NeoForge 的内部实现。

**可串食材标签：**

- 所有具有食物属性的物品默认可以串入，无需登记。
- 非食物原料加入 `#kaleidoscope_grilling:skewerable_ingredients` 后可以串入；本模组的骨头、末影珍珠和黏液球使用此方式开放。
- 需要禁止串入的特殊食物加入 `#kaleidoscope_grilling:unskewerable_ingredients`，禁止标签优先于默认食物判定和允许标签。

**固定串数据格式：**

第三方数据包可在任意命名空间的 `grilling/*.json` 中追加固定串。`id` 和 `cooked_result` 均保留完整命名空间，不再要求使用本模组物品或遵循 `raw_` / `grilled_` 命名。

```json
{
  "skewers": [
    {
      "id": "example_mod:raw_cheese_skewer",
      "cooked_result": "example_mod:grilled_cheese_skewer",
      "ingredients": [
        ["#example_mod:cheese_wedges"],
        ["minecraft:beetroot", "example_mod:onion_slice"]
      ]
    }
  ]
}
```

- `ingredients` 支持 1～3 个槽位。
- 每个槽位是候选选择器数组，支持物品 ID 和以 `#` 开头的物品标签。
- 生串物品可加入 `#kaleidoscope_grilling:raw_skewers`，方便其他配方与兼容逻辑识别；已在固定串数据中声明的 `id` 即使未加入标签，也可被烧烤架识别。
- `cooked_result` 是推荐必填字段。旧数据缺失该字段时，仅对同命名空间且名称以 `raw_` 开头的物品兼容推断为 `grilled_`。
- 熟串映射不存在或返回空物品时，烧烤架安全降级为迷之烤串。
- 签谱库存扫描使用同一选择器规则，因此标签原料可以正常快速串制。

**公开 Java API：**

- `SkewerCompatApi.registerIngredientRule(id, rule)`：为带 NBT、组件或运行时条件的特殊物品返回 `PASS / ALLOW / DENY`。
- `SkewerCompatApi.registerCookingRule(id, rule)`：为不能用固定 JSON 表达的生串返回自定义熟制 `ItemStack`。
- Java 回调应在两端公共初始化阶段注册，保证客户端交互预测与服务端结果一致。
- 普通固定串优先使用 JSON 与标签，避免产生不必要的加载器耦合。

### 13.3 食物效果继承

1. 固定烤串先读取自身基础 Buff；秘制烤串先按保存的原始 `ItemStack/NBT` 依次模拟食用串入食材，只继承食用效果，不继承原食材饱食度与饱和倍率。

3. 如果食物带有 **🔥热** 属性，食物自身 Buff 持续时间翻倍；秘制烤串通过模拟食用继承到的原食材 Buff 也视为食物自身 Buff。
4. 如果使用了特制调料，且食物仍处于 **🔥热** 状态，则额外添加调料 Buff。
5. 调料 Buff 与食物自身 Buff 独立计算；折耳根粉只影响调料 Buff 时长，不影响食物自身 Buff，也不改变热属性持续时间。

辣椒油
+
热状态

= 最终效果

### S-02 辣椒油原料修正

> 关联 §4 工具与调料配方表格、§7 新增加工品

**修正前：** 辣椒油 = 菜籽油 + 红辣椒沫×3 + N

**修正后：** 辣椒油 = 菜籽油 + 红辣椒粉×3

**原料链调整：**

### S-03 炒锅油层视觉：BER 叠加渲染

> 关联 §4.1 热属性系统

**背景：** 森罗厨房炒锅的油面只有一个通用纹理（`pot_oil.png`），无法区分菜籽油、辣椒油和熔岩辣椒油。

**方案：** 本模组注册一个 `BlockEntityRenderer` 监听森罗厨房的 `PotBlockEntity`，在锅体油面位置（Y=1.2 处）叠加渲染一层半透明彩色平面。

**实现细节：**
- 不使用新模型或 blockstate 变体，不修改森罗厨房的资源文件
- 渲染器读取本模组 Mixin 注入的 `grilling$oilType` 字段
- 按油种使用不同颜色（`RenderType.translucent()`）：

| 油种 | 颜色 |
| :--- | :--- |
| 菜籽油（默认） | 金色 #FFD700 |
| 辣椒油 | 橘红 #FF4500 |
| 熔岩辣椒油 | 暗红 #8B0000 |

- 彩色平面位置：X/Z 从 3/16 到 13/16，Y=1.2/16，与森罗厨房 `pot_has_oil.json` 中的油层元素一致
- 颜色透明度约 50%，叠加在锅体原有 `pot_oil.png` 纹理之上
- 仅在 `grilling$oilType` 非空时渲染（即只对本模组三种油生效）
- 后续如需替换为纹理贴图，可在 `PotOilRenderer` 中添加 `RenderType.entityTranslucent()` 的贴图绑定

**不属于本模组渲染范围：**
- 炖锅不使用油，不叠加渲染
- 原版油脂使用默认 `pot_oil.png`，不叠加本模组渲染层
